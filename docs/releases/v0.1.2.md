# LocalXiv 0.1.2

This release draws the Overview and the Blog figures as Mermaid diagrams in a hand-drawn style, and it changes how the Blog Tone setting shapes the prose.

## Changes

- **Mermaid figures.** The model writes each Overview and Blog figure as a Mermaid diagram, and the application draws it with Pele. The Diagram checks measure the drawing: its shape, the smallest text, the words in each label, and the values it must show. Each failed check goes back to the model as a correction. The Figure library and the Scene layout are removed. A figure that a 0.1.1 or older build saved still shows, as an image.
- **One Overview diagram from a plan.** The Overview plans at most 7 items on the path of the core mechanism and 1 or 2 headline numbers, then draws them as one diagram. An optional result chart sits below it. Component hover works on flowchart and block nodes, and **Enlarge** shows the diagram in the figure dialog.
- **Hand-drawn look.** Figures use the Excalifont font and rough outlines from roughjs, on the page and in the PNG, PDF, and SVG exports.
- **Figure drawing rules.** The Overview and Blog prompts share one set of drawing rules: the figure's message as a note beside its part, a worked example with values, a job for each colour, and a layout pattern that carries the idea. The rules also state how Mermaid places subgraphs and where bold text shows its asterisks, and the shape corrections repeat the subgraph rule.
- **Tone sets the register.** Every Tone keeps one plain-style core based on ASD-STE100 Simplified Technical English. Casual uses "you" and "we", contractions, one question at most, and one analogy. Semi-formal uses "we" and the third person, with no contractions or questions. Formal uses the third person only. The Section check rejects what the Tone leaves out, the phrase "the running example", and words that mark model-written prose.
- **Blog length.** Each section prompt states the section's word count, and the Section check allows at most 1.3 times that count.
- **Blog results.** The Blog narrative writes each main result as a measure from the paper's comparison table: the dataset, the metric, which direction is better, and the paper's best variant beside its comparators.

## Verification and limitations

For this release, ruff found no problems in `papers`, `app`, and `tools`. On Python 3.14, the component suite ran 250 tests: 9 skipped and 1 failure. The failure is `test_one_text`, which reads the newest local parser corpus run, and that run has no `document.json` files. The JavaScript test passed.

Two live Blogs ran on 2026-10-29 with claude-opus-5-5 on one paper, in the Casual Tone at Medium length. With the 1.3 word ceiling, 1 of 7 section requests was rejected. In the second run, 2 of 3 figures were omitted. The drawing rules and the corrections in this release address the causes of those omissions, but no live Blog has run with them. The details are in [the 2026-10-29 Blog readability research](../blog-readability-research-2026-10-29.md).

Open items:

- No live Overview or Blog has run with the final drawing rules and the hand-drawn look.
- The open items of 0.1.1 stay.

AI explanations and Chat remain experimental. AI requests send selected paper content, and for Chat the Highlights and Notes of the Paper, to your configured provider and may incur charges. With the Papers with Code setting on, LocalXiv sends search text, bibliography titles, and the arXiv IDs of the Papers you open to paperswithcode.co.

## Installation

Requires Apple Silicon and macOS 26 or newer. Download the DMG and drag LocalXiv into Applications. Finish active jobs before updating. Your library and settings remain on your Mac. Updater-enabled builds can use **LocalXiv → Check for Updates…**.

This preview is ad hoc signed, without Apple Developer ID signing or notarization. macOS may block the first launch.
