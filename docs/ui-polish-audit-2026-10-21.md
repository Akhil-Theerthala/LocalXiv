# UI polish audit, 2026-10-21

This audit compares the LocalXiv user interface with the 111 rules of [the UI rule book](ui-rule-book-2026-10-21.md). The rule book merges 180 rules for premium Mac apps from Apple's Human Interface Guidelines, WCAG 2.2, Emil Kowalski's design-engineering rules, and books and guides on reading typography. Each rule has an id, such as `R-TYP-1`, a check, and its sources. A skeptic checked each rule against its sources.

## How the audit ran

1. Eight auditors read the code and screenshots of one surface each: Home and search, Paper typography, the Overview and the Blog and Split view, the margin and Chat, the Notes page, dialogs and feedback, the Native shell, and motion and the visual system.
2. A skeptic for each surface tried to refute each finding against the code. The skeptics kept 251 findings and refuted 24.
3. A ranker merged the findings that name one defect into one item and put each item in a group.

The audit made no AI requests and sent no Chat questions. The screenshots come from a copy of the library in a browser. Nothing here comes from a run of the Mac app.

## Results

The user chose these scopes on 2026-10-21:

- Fix all A1, A2, and C items before the release.
- Keep `scale(.97)` as the press feedback (Emil Kowalski), not the AppKit darken of R-MOT-9. Buttons that had no pressed state got the same scale.
- Keep the Reading theme on the whole window. R-COL-1 is not applied.
- Keep each B item as it is.

The fixes are 175 commits after the commit that added this doc. Each commit body names its audit items. Two review rounds read the whole diff: one reviewer for each batch, then eight reviewers with separate lenses. Two skeptics checked each finding, and repairs fixed 38 confirmed findings. A last review of the repairs found no new defect.

Checks:

- The test suite passes: 185 tests, 5 skipped.
- In a browser, on a copy of the library: Paper typography in Light and Dark (heading space, link underline, captions, Dark figure plates, text size 36 px with the passage held), the Blog and Overview AI notes, the selection toolbar with Copy, word snapping of a new Highlight, the Notes page filters, Library rows, the Remove dialog (title, counts, no default button), and the Settings dialog.
- In three `tools/native_shot.py` runs: the new menu items and keys (Hide Toolbar ⌥⌘T, Show Reading Preferences…, Search ⌥⌘F, Use Selection for Find ⌘E, All Notes ⇧⌘N, Highlights and Notes export and copy), the find bar under the toolbar, Use Selection for Find, the Aa popover at 36 px and Actual Size, the Highlight colour submenu in the Paper context menu, the native Library row menu, the Undo title ("Undo Delete Note"), the More icon, and the Settings window.

Not checked: VoiceOver, Increase Contrast and Reduce Motion in the Mac app, the sidebar at the Small and Large icon sizes (shell-20), the saved window place at launch (shell-33), a web process crash (shell-32), download failures (shell-13, shell-14), and a failed job in the Activity line (shell-09). In the first native run, the Library opened scrolled down by the height of the Continue reading card while the window was not key. Two later runs with the same steps opened at the top.

Found after the audit, not fixed: Paper table cells use the body's `hyphens:auto`, so a narrow column breaks a short word over three lines ("# re-spons-es" in the dataset table of arXiv 2502.03407, chapter 3.2). A fix must keep tables that set column widths from scrolling sideways.

## Groups

| Group | Items | Meaning |
|---|---|---|
| A1, polish | 94 | A fix to typography, motion, colour, focus, VoiceOver, or copy. No new control and no server change. |
| A2, new behaviour | 18 | A fix that adds a control or an action, or changes the server or a job record. |
| B, decision | 21 | The fix changes a recorded decision or a release string, or it has two good answers. The default for each item is to keep the app as it is. |
| C, native | 33 | The fix is in the Native shell, or only a run of the Mac app can show the defect. |
| Deferred | 1 | The fix cannot be checked in this audit. |
| Refuted | 24 | A skeptic showed that the code meets the rule, or that a recorded decision covers the finding. |

Each ID names the surface and the auditor's number: `home`, `paper`, `OV` (Overview), `BLOG`, `SPLIT`, `MARGIN`, `notes`, `DLG` (dialogs and feedback), `shell`, and `XC` (cross-surface). An item that merges findings has more than one ID. The level is the severity, then the effort: S, M, or L. "Confirm first" marks an item that the skeptic could not prove from the code alone.
